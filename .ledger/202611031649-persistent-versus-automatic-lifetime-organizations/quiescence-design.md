## Property and design

A live person can commit automatic permanent departure only against a current bridge/connection-bound quiescence agreement. Accepted transport input and preparation are real activity even when the runtime's historical idle snapshot still says idle. Loss of the observation channel invalidates proof. A physically proven exited writer does not require a live agreement; that remains the existing process-proof boundary and is excluded from this live-writer model.

The runtime first reserves input admission with a distinct journaled quiesce command. Pending accepted/delivered turn-producing commands block this reservation. Runtime inputs arriving after reservation are explicitly refused, not accepted and silently lost. The current bridge agrees only after fresh host idle/pending/preparing checks and seals local input before acknowledging. New local input while sealed is explicitly rejected. Existing accepted/preparing work must settle or be explicitly rejected before agreement. Permanent commit still checks current root/generation/membership/responsibilities and additionally requires the exact live agreement. Failure/cancellation invalidates proof before releasing the bridge. The bridge gate survives reload/disconnect until the new connection invalidates old proof and releases it. Old or disconnected bridges cannot furnish proof.

Implemented owners: dissolutionBlocker and startsTurn classify accepted/delivered input. Runtime.reserveInput reserves admission before issuing quiesce; commandRefusal and dispatch refuse new turn inputs. Bridge.applyInputCommand seals through sessionInput before acknowledging. Runtime.commandProgress accepts proof only for its exact dispatched connection/ticket; inputQuiet rechecks current binding and physical writer identity, including unknown and older live writers. departureCandidate invokes it again at permanent commit. resetInputAgreements invalidates every matching launch before releasing a retained seal; pruneInputAgreements releases canceled or newly blocked candidates; disconnect and startup recovery discard volatile proof. The existing retireSession transaction and writer/file cleanup remain authoritative.

## Model and checks

Three independent actors are represented: runtime, bridge and input producer. RemoteInput is accepted transport; Deliver and Start are separate preparation/execution boundaries. Observe updates a stale snapshot independently. Reserve, Agree and ReceiveAgreement are separate socket/actor steps. Frozen bridge state survives runtime Crash, while reservation/proof do not. Reconnect increments connection binding; old replies cannot bind a later ticket. Release follows invalidation. A pending root close can be canceled before Commit.

Two distinct ticket values and three connection bindings distinguish retries/reload from identity reuse. Repeated input/observation and runtime crash/restart explore their finite graph. Existing root/tree/generation/file cleanup remains in organization-lifecycle.tla; this companion does not extract or prove SQL, SDK hook coverage, process identity, a physical crash or liveness. One root closing request is assumed; its cancellation is represented, not a later independent close epoch.
