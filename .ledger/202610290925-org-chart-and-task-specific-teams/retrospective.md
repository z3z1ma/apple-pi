The implementation reuses the existing runtime for people, goals, reporting and channels. The most useful extra checks crossed real boundaries: the actual runtime socket exposed nested receipt ambiguity that a Commands stand-in missed, and actual Electron navigation checked a route guard that browser fixtures bypass. The integration owner kept builds stable during host checks and kept later renderer revisions separate from earlier proof. Build39 browser proof now passes: nine Org cases plus two targeted profile cases. Build39 actual-Electron and freshness proof also passed. Implementation was committed and then activated with explicit operator approval. A fresh live preflight found no daemon-owned children or pending non-mail controls; all 11 Pi process identities and actual socket connections survived the replacement. Reporting and hire dates remained unchanged. No live test team was used.

## Learnings

An idle worker with an unfinished assignment can be blocked by a provider failure without being able to report it by mail. When a lane stops producing its promised artifact, verify the files and inspect the session's recorded `last_error` before sending more work or waiting. Reassign the bounded work to an available colleague when the provider cannot run; preserve file ownership so a recovered worker can resume without overlap.

A failure outside a lane's source can still belong to its adoption: distinguish where a defect originated from who must resolve the integration. The participation fixture reset user_version to an old revision while retaining the newly adopted hired_at column, so migration attempted to add it twice. Restore the actual historical physical schema, including removal of later columns or indexes, while retaining the audience behavior assertions. Request bounded ownership rather than dismissing the failure as unrelated or widening scope silently.

The runtime's outgoing assignment and readiness mail share command-ID prefixes with their parent operations. Recovery readers must select the relevant command kind as well as the prefix. Ready-team membership belongs in the kickoff's recorded roster, not in mutable process start times. Profile observation, conversation reads and channel acknowledgment need separate checks.

## Improvements

Use evidence.md as the check index rather than repeating test claims across task documents. Distinguish source checks, built-renderer fixtures, actual Electron entry and live activation. The initial combined channel/participation run contained a failing historical fixture; its later isolated repair is separate evidence, not a retroactive all-green result. The operator's visual corrections changed the interaction model twice: a responsive overview removes the all-tree horizontal forest, while a fitted top-down selected tree keeps familiar drag geometry. Work history then became the context that identifies a team. Scope labels must distinguish recorded task ownership from today's reporting tree; moving a person cannot rewrite historical credit. Compact work summaries preserve chart space, while explicit expansion exposes the complete recorded history.

The gap between assigned and active work mattered under urgency. Independent ownership helped only after stalled provider lanes were detected and redistributed, and the root kept the integration and rendered visual judgment moving. More passing tests did not excuse cramped avatars, redundant reporting buttons or an obscure close affordance. Final screenshots, direct interaction checks and operator feedback answered different questions.
