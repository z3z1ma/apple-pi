# Retrospective

## What Mattered

The operator redirected optimization machinery into an observability substrate: rich work/relationship primitives and inexpensive recorded facts, interpreted by persistent managers. All seventeen source increments are approved and committed; optional economics did not become a prerequisite for action. The final scripted manager demonstration makes ready work, relevant experience, assignment and unchanged blockers legible without claiming autonomous judgment.

The most consequential repairs were at boundaries: historical ownership versus current membership/audience, immutable economic events versus later explanations, lost measurement qualifications, every admission producer for durable identity, and post-SQL filesystem cleanup ownership. Different reviewer lenses supplied executed counterexamples rather than repeated narrow happy paths.

Independent working-tree checks, review copies, committed blobs and live deployment were kept separate. Authorized rollout moved the actual shared runtime from schema 27 to 29 after a consistent private backup and guarded restart. The operator refreshed the root session; new native tools/guidance and a successful live org_work call verified the refreshed surface. The separate composition failure is not an organization-feature repair.

## Learnings

- Preserve expressive concepts while cutting implementation machinery. The operator accepted the brief's intent, not every proposed engine or workflow. The later observability direction sharpened this: expose facts cheaply and let managers judge; fitness and scenarios are instruments, not required rituals. Historical database contents describe the system that produced them, not necessarily today's runtime.
- Before specifying a historical metric, trace each input to its durable producer. `needs_you_since` is mutable current state, not an attention-duration history; prompt events measure a different fact. Check that adjacent windows add up without charging accrued delay twice. Review later found the same class of error when current organizational roots were used to select past work: current ownership and membership at the event's time answer different questions. Verify each consumer with the same fixed past window before and after a later join or move; present-roster expertise deliberately includes pre-join experience, unlike past economic and wait windows.
- Use hours and parallel work in agent-economic examples, not human-day assumptions. Express cost of delay per hour and choose horizons appropriate to the decision.
- Ask returning reviewers to read the revised file from disk, and check quoted lines against that version before acting. A cold reader reused a superseded specification and reported contradictions that no longer existed.

- Validate scratch fixtures against production contracts before interpreting a negative reproduction: give every `work_tasks.bundle` a distinct path and put valuation lines before the first `# ` heading. Otherwise setup can fail or a task can silently be unvalued instead of exercising the reader. Direct `postToThread` calls use the internal `ThreadPost` contract: supply an explicit thread ID and another known recipient, rather than copying the public mail arguments. Assert the returned result with its actual error text before interpreting the experiment.
- Check the exact baseline predicate before calling behavior a regression or an established contract. A review recollection incorrectly called coverage cumulative; the prior `opened_at < to && closed >= from` predicate already excluded tasks closed before the window. Comparing the baseline prevented an invented requirement from changing implementation.

- Keep eligibility, requested-window economic relevance, and cutoff wait ownership separate. The org_waits repair first lost a cancelled task's surviving wait by using priced tasks as candidates, then admitted temporary-only program steps by dropping eligibility. Establish relevant ownership before goal-file access; otherwise unrelated foreign files can fail a caller's query. These contracts live beside the fitness adapter.
- Durable ownership must outlive its recorder. Artifact-only links survived temporary-peer deletion but lost resolution authority until the originating organization was stored atomically without rewriting provenance. Migration fixtures must pin the physical historical version they reconstruct, not an offset from the latest migration; the new origin migration exposed a skipped lifecycle backfill in a relative-version fixture.
- Historical audiences are not current access. Ordinary channel moves deleted participant rows and rewrote fixed past communication counts. Operator-approved join/leave facts, atomically stored with access changes, fixed that without preserving access. Migration seeds only surviving evidence and discloses lost earlier departures. Invitation flags and read cursors are separate from audience transitions.
- Explicit escalation identity required checking every consumer: retiring a requester is not withdrawal, and fitness plus Agent World must still recognize the native kind. Subject-only legacy mail cannot be truthfully reclassified. Source workplace tests passed while the committed Electron reader was stale; rebuild with `npm run build:world`, run build-consistency plus affected behavior tests, and include generated artifacts in the review freeze and commit.
- Measure repeated-query costs before optimizing. Communication's many point membership queries repeatedly parsed unrelated cost/prompt facts; a synthetic scaling trial exposed the hotspot. Structural point queries now skip those facts while callback replay retains full ordered compute/question observations. The timings demonstrated that bottleneck, not a production latency guarantee or a reason to add arbitrary caps.

- Before adding telemetry, trace existing facts across their transaction owner. An intern saw mutable `work_focus` and untimed `work_changes` and concluded focus history was unavailable; reading `runtime.applyWork` beside `changeWork` exposed the atomic pairing with the `<command_id>:post` task message and its execution timestamp. Replaying retained pairs supplied estimated historical focus without a new store. Missing pairs cannot be replaced with today's focus or treated as proof that all missing intermediate transitions are detectable. The durable coupling and its limits are recorded in the fitness source context.

- Establish the consumer's accepted attribution convention before calling loss of emitter identity a provenance defect. A controlled different-focus trial showed temporary-peer compute following its accounting caller's focus; recovering the accepted plan established that this was intentional. Preserving a more detailed emitter allocation would have changed policy, not repaired the agreed explanation. The fitness context owns the caller-focus invariant.

- Structural ownership is not recording-time existence. A prediction naming a missing task became incorrectly verifiable when production `changeWork` later created that exact ID. Check retained opening at or before recording separately from ancestry, before valuation file reads. Unknown opening stays unverifiable; do not guess an anticipated-task binding. This contract lives in the scenarios context.
- Finite inputs can still yield unrepresentable analytics. Two finite forecast operands overflowed their difference, and a positive relative horizon rounded to an empty epoch interval. Check derived calibration and finite advancing resolved endpoints rather than inventing monetary caps or minimum durations. Report unavailable results explicitly; JSON silently converting nonfinite values to null is not an explanation. These guards belong in the adapter, not a new evaluator.
- Preserve measurement qualifications through analytical wrappers. Keeping only `realizedFitness.total` produced apparent perfect calibration despite additional unvalued actual work. Prediction output must retain coverage, incompleteness, exclusions and attention limits; incomplete observed valuation withholds numerical error, while constant disclosed exclusions alone do not make every prediction unscorable. The scenarios context owns this distinction.
- Compare the snapshots actually at issue. A late author-manifest mismatch did not mean the review-worktree copy was stale: that copy already matched the current files. Distinguish author-run, current-tree, review-copy and committed-byte evidence. After a late assertion/context change, read the new test and renew its proof rather than borrowing an earlier count, even if production bytes are unchanged.
- Durable identity must guard every admission producer, not only explicit session starts. After ordinary/fresh-program reuse was blocked there, Tendai reopened a retained native transcript through SessionManager.open and the real bridge without its old program environment: ordinary hello recreated the UUID and charged new spend to its old caller. Retaining a transcript does not authorize reactivating its temporary person. Apply durable identity before hello person/incarnation/facts writes while preserving valid live-program reconnects. Independent real-bridge negative and positive controls verified the repaired boundary; this is not native CLI end-to-end proof. The bridge/runtime contexts own this coupling.
- Retention widens cleanup candidate sets as well as historical evidence. Waylon's sequential holder disposal with a real file-removal failure exposed a journal owned by the earlier holder, outside the current disposal's pending-receipt filter; launch ownership was released prematurely. Select receipt ownership from the current operation's IDs. Verify failure and retry after sequential disposal, including persistent-database reopen, rather than relying only on SQL rollback or successful deletion. The program-peers context owns this cleanup contract.
- A surviving legacy launch row proves that launch's caller, not lifetime ownership across an earlier discarded ID. Waylon exercised pre-upgrade admission reuse and showed later observed ownership importing older spend into another organization. Preserve first retained identity evidence including unknown, and avoid reused current-row or later first-change.from backprojection for ambiguous ancestry; actual structural to changes remain usable at their own event times. Unknown caller/initial ancestry are conservative reader projections, not fabricated migration events or reconstructed eras. Old-method/current-dependency reruns verified the distinction without claiming a whole-old-runtime trial. The program-peers and fitness contexts own these provenance rules.

- Keep verification-stage outcomes separate from the shell wrapper status. Clean untracked files checked with `git diff --no-index --check /dev/null <file>` can return 1 with no whitespace diagnostics because no-index mode reports the added-file difference. Inspect the diagnostics and finish the after-hash comparison explicitly if `set -e` stops the wrapper; neither an early passing suite nor the wrapper exit alone proves that all final checks completed.

- Output parity alone does not establish a new adapter's promised input contract. The include-self roster recognized the caller's name while the inherited recipient resolver excluded self; equivalent native/command failure did not satisfy the new exact-name promise. Normalize a unique command-selected name to its ID, preserve genuine ambiguity, and compare supported names with native selected-ID output rather than redesigning addresses.
- A scripted manager is integration evidence, not an autonomy evaluation. Assert actual indexed experience, native actions, stable references, before/after readiness/holders and an unchanged blocker; label the predetermined choice explicitly. Prompt guidance supplies goals and relevant evidence, not a fixed all-tools ritual or ordered staffing prescription.
- A rollout script's local `const process` shadowed Node's global and threw before SIGTERM after the backup had validated. Name diagnostic results `processInfo`, identify the exact action boundary when reporting a script failure, and recheck live guards before retrying. This was a pre-action script error, not a daemon or migration failure.

- Attached-peer pi_exec composition failed its generated captured-tool precheck before any peer turn, even for a minimal snippet. Direct native mail/tools kept work moving. After root reload, basic `1` still fails with invalid-type-form (`tuple[EllipsisType, Unknown]` in an annotation). No guest action occurred; no composition proof or diagnosis of the offending generated stub is claimed. Keep this separate failure explicit rather than attributing nonexistent peer output or expanding the organization implementation to repair the engine.

## Improvements

Trace durable inputs and all relevant producers before sharing a projection. Exercise both SQL rollback and post-commit file failure/retry. Keep freezes tied to actual assertions and artifacts, renew affected proof after changes, and widen review when material follow-on failures justify a new lens. Keep administrative narration and speculative exploration proportional to the next useful action. Source approval, live restart authority and session refresh are separate gates.
