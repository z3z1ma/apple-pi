Additional boundaries:

- **No separate package graph.** Components are internal source directories; the root manifest is the only Pi package. MCP is provided by Pi, not a separately installed Apple Pi dependency or linked repository.
- **Wiki graph is derived, not stored.** `.wiki/` Markdown pages and their Obsidian `[[slug]]` links are the source of truth. `wiki_lint` and `wiki_references` scan them on demand; there is no wiki database, cache, watcher, registry, embedding index, or synchronization service.
- **Code context is read from disk, not indexed.** `.context/<path>.md` context files are the source of truth. Delivery state is the hash marker in the model's current context; there is no delivered-file table, symbol index, AST parse, or embedding. Only top-level `read`, `edit`, and `write` calls are covered.
- **Pi owns compaction.** Every provider and the private pair session use Pi's native LLM summarizer. The notebook appends open learnings as one persisted message after compaction. Provider checkpoint requests, opaque replay, custom pair reseed summaries and retention policies are outside apple-pi. Codex's ChatGPT backend protocol differs from Pi's `openai` direct-token OAuth route; sharing an item name is not protocol parity.
- **Shared conclusions, archived evidence.** Both programmers curate sourced conclusions that improve later decisions beyond ordinary summaries. Full pair reviews explicitly retain useful conclusions; observations remain recallable history rather than injected guidance. Retention is not driven by pool fullness, fixed lifetimes, or relevance scores.
- **Session ledger is authoritative.** Notebook edits and retirements append to session JSONL. Live context is derived from the current branch; compaction does not relocate or freeze the notebook.
- **One assigned-work model, rather than optional backlog and to-do systems.** The former optional extensions and their separate checklists, persistence, widgets, and background-agent execution are removed. Goals and context belong to explicit task assignments, with ledger bundles for durable work and ephemeral bundles for temporary work. Process backgrounding, reminders, and monitors remain the managed-task lifecycle; communication remains in the session-state runtime.
- **One active-work surface and manager.** Managed tasks, running Pi Exec programs, and running interns publish domain-owned rows into one shared above-editor renderer with global width/height bounds and terse domain counts. `/work` and `Ctrl+W` open one tabbed management modal with Tasks and Pi Exec tabs; `/tasks` remains a direct-tab alias. Domain-specific detail and actions stay with their owners instead of moving into a generic operation model.
- **Branch search is the model's tool and judges with commands.** The main agent calls `search_branches` with judge commands that print a number, often from the user's suggestion, and gates such as the test suite; attempts that pass every gate are ranked by those numbers, optionally with a model choosing among them. Users do not start searches directly. Earlier designs are kept at git tag `branch-search-v1`.
- **The organization is one tree of lasting people, not a swarm of disposable children.** Peer sessions are people with lifelong roles from the `roles/` catalog, and one-shot reading belongs to cheap interns (`explore`, `research`). Rejected: mail scoped to the tree (mail reaches anyone; only assignment, reporting, and escalation follow the tree); a person changing roles (a new need is a new hire); a structured handoff artifact between people (they give each other goals and say what they verified and what they believe); caps on team size, self length, or the catalog; a second memory store for the self (it lives in the person's transcript and the session-state facts, beside the notebook, never distilled); and minds named through model profiles (a role names exact model ids in order, so its mind is the same on every machine that has the model). Roles files are the catalog; there is no roster file, no `--coordinator` flag, and no per-project redefinition of a role's mind.
- **Role-scoped management.** Roles with `manages: true` receive organizational insights, peer delegation, the manager charter and role catalog. Tree position alone grants none of these; everyone retains general task links, mail and ordinary tool composition. The human `/org` command remains available regardless of role.
- **Organizational observation, not a controller.** `bottlenecks`, `progress`, `coordination` and `experience` expose recorded conditions; `economics` and scenarios are optional economic instruments. People investigate causes and use existing management tools, or deliberately stay stable. There is no automatic restructuring rule, universal score, fixed staffing threshold or required forecast before action. See [the organization](organization.md#evidence-informed-adaptation).
- **No compatibility implementation.** There is one current path, not old/new variants.

## Rejected delegation and workplace ideas

These were removed or considered and turned down when peers in the organization took over all cross-agent work. Do not restore them by accident.

- **Custom agents.** User and project agent definitions (`.pi/agents`, `.agents/agents`, `~/.pi/agent/agents`, `.pi/subagents.json`) are not loaded. A role in the catalog is the only way to define a kind of person, and it names the mind, posture, and obligation for life; a second definition format would give two answers to who someone is.
- **Background subagents.** The in-process delegation runtime (background runs, resume, steering, nesting, parent clarification forks, coding children with notebook access and completion review, and the live team view) duplicated what peers do, held memory (one root process kept 37 finished children alive for three days), had lifecycle problems of its own, and wrote child rows that no view showed. Parallel reading is several intern calls in one reply; lasting or parallel work goes to peers, each a root session with its own transcript; programs call peers through `pi_exec`.
- **Pushed channels.** Team channel messages are pulled: people do not read every message in every channel as it arrives, and pushing them would fill each person's context and interrupt its runs. Only an explicit `notify` list requests selected accessible people's attention. Addressed group mail pushes each reply for conversation-speed work; ordinary names in channel prose are text. Skills choose meeting/review/incident procedures over these primitives rather than native business-process entities.
- **Assignment tickets beyond tasks.** Every piece of work is a task bundle (a ledger task or an ephemeral task) with a `task.md` goal and a task thread; the runtime records who holds it, who assigned it, and when. Links relate existing tasks, people and evidence; they are neither hand-off records nor another work record beyond tasks and assignments. A separate ticket or hand-off record would be a second copy of the goal, and the organization already rejects a hand-off schema.
- **Calendars.** No time slots or availability calendars: people here have no working hours, and `remind_me` plus ordinary mail/channel discussion cover a recurring check-in. Read receipts, reactions, typing indicators, and status emoji are left out too; directory presence (working, idle, asleep) is enough.
