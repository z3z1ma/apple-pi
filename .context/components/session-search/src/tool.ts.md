## file

Resolve exact entry/call/file addresses against the selected scope before excluding the issuing assistant entry from discovery. History, file and touched discovery share that selection. Native executeTool child IDs extend their persisted parent ID as caller/n, including recursively nested calls.

Why: issuer exclusion prevents the current query from becoming its own evidence, but historical exact addresses must remain usable.

Personal regex detection, exact local recovery, file/touched discovery and expansion keep their legacy paths. Indexed history pages use index offsets and eligibility-matched totals throughout. Task discovery uses indexed words even when punctuation selects the personal regex heuristic; task scope with legacy modes is a visible refusal.

Runtime, database and body-read failures raise native tool errors. Explicit permission refusals and defined unsupported requests remain ordinary visible results. The index candidate is evaluated separately from the withdrawn ranking/query pipeline. Treat displayed discovery as a bounded selection; recover complete evidence through stable source addresses.

Why: source availability, top-result relevance and displayed-answer sufficiency are different outcomes. Correct extraction alone does not establish complete discovery or better recall.
