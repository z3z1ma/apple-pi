This is failure-only root-session recovery. The global boolean grants permission; the existing model-profile catalog supplies choices. Healthy runs resolve no replacement pool and make no model/effort changes. The native conditional action is a required capability, not an unconditional-setter fallback. A compatible build also cancels the logical run and pending selection when abortRetry cancels an active countdown; otherwise a still-live settlement marker can revive cancelled work. The isolated native source patch includes that correction. Method presence alone cannot prove these semantics. Keep missing capability visible and nonfatal.

`turn_end` must await selection: Pi can retry or compact before final settlement, and a late selection would send that work to the exhausted provider. Capture the active signal here; final settlement can have no active signal. The native action owns auth-wait selection fencing, including same-value/ABA requests. False can follow a committed change during notifications, so it authorizes stopping, not restoration. Auth failure and invalidation share that false result; trying another target could overwrite a newer choice.

The episode's attempted-provider set and pending-continuation marker have different lifetimes. Keep attempts through native retries and tool turns. Clear the marker on any subsequent assistant reply before classifying it, including an unknown error; otherwise an already executed native retry can be followed by an unintended extra continuation. Consume its continuation vote once at settlement, but keep the signal/requested record until a reply or settlement. A later settlement handler can make a manual choice after our continue result was returned; abort that native handoff rather than only clearing local state, because the native continue vote already exists. Both later-model and later-effort caller controls reproduce the old gap; the task's ContinuationHandoff model separates grant from dispatch. The configured distinct-provider set supplies the bound.

Each pending async selection retains its episode object. Reset the reference before aborting its controller; stale completions return before reading a replaced extension context or aborting a newer run. Selection-in-progress belongs to that episode rather than a global flag, so an old finally path cannot change a newer episode's ownership. Effective manual changes interrupt pending recovery; native request-entry fencing handles changes during auth without own-event inference.

Registry lookup can execute provider callbacks. After a successful native selection, publish the provisional selection and pending marker before revalidating metadata. Recheck episode identity and signal after those callbacks and after notification. At settlement, recheck them after metadata lookup too. A newer manual effort change at that boundary must stop old compaction/continuation while leaving the new physical selection intact.

Chain incoming event.entries when adding the failed-entry context edit: native boundary results replace the accumulated list. Expected ModelProfileError configuration stops produce the friendly notice once; unexpected errors still reach the native extension error channel.

Use metadata entries plus notifications/stderr for notices, not model-visible custom messages. Adding a user-like status message can change native compaction cut points and conversation semantics. Raw failure history stays in the transcript; only its projection is hidden through the supported context-edit draft. Native continuation owns completed tool results; this layer replays neither prompts nor tool calls and claims no exactly-once semantic effect guarantee. Independent compaction errors, including pre-prompt compaction before a failed assistant turn, do not enter this recovery hook.

Program processes are excluded, including all captured review attempts. Named lasting workers are transcript sources for disposable review forks, not borrowed executing sessions. A colleague turn attached to an already-running lasting person is still that person's ordinary root turn, with no captured review policy. Internal fork callbacks also skip without resetting parent state. Private pair/BTW sessions and interns do not load the extension. Register this extension after session-state so role startup resolves before workload priming.
