## file

The one change-selection owner for review capture, freshness, code sign-off, explanations and Pi Exec evidence. An exact range never acquires merge-base semantics; only `branch` does. Repository paths come from separate rev-parse queries because a path may contain a newline; endpoints are one batch whose output must be exactly two object IDs (commit, tree) per name, which also refuses range syntax such as `HEAD..HEAD`. rev-parse echoes `--end-of-options` as an output line; the parser drops it. `cat-file --batch -Z` replies such as `<name> missing` or `<oid> submodule` carry no body; any header other than `<oid> <type> <size>` means absent.

Every command after locating the repository runs in an isolated context: a private Git directory written directly (no `git init`), the author's worktree as GIT_WORK_TREE, a private or supplied object directory, and the author's objects as a quoted alternate (a colon in the path otherwise splits the list). The private directory has no config, attributes, hooks or filter definitions, so `.git/info/attributes`, configured filters and repository config cannot run programs or transform bytes there. It copies only `info/exclude` and split-index shared files; path-spelling and ignore settings (`core.ignorecase`, `core.precomposeunicode`, `core.excludesfile`) are passed explicitly. Raw flags also disable `core.attributesFile` and the empty-tree attribute source covers worktree `.gitattributes`.
Why: review found that an empty attribute source left `.git/info/attributes`, `core.attributesFile` and XDG attributes able to run clean filters, and that the copied author index carried assume-unchanged/skip-worktree flags and stat-clean entries whose blobs had been converted (CRLF on disk, LF in the index).

Mutable targets copy the index with its modification time (racy-git compares entries with the index file's own timestamp; a fresh copy hid a same-second, same-size edit) and run `git add -A` against the copy, as `git stash create` does. Before that, the copy drops assume-unchanged and skip-worktree flags (one update-index command per flag: with both options, Git applied only one to paths from stdin), and tracked files that the author's current attributes or autocrlf could convert are hashed in-process and re-added without stat data when their disk bytes differ. Only those suspect files are read. The operator accepted the remaining gap: a file staged under a conversion setting that was later removed keeps its stored blob, because the stat cache calls it clean. Closing it would mean hashing every tracked file on every snapshot. `git add` uses `core.bigFileThreshold=1`, so bulk check-in writes new blobs into one pack (5,000 untracked files: 3.5 s loose, 0.8 s packed on this machine).

openTrees is the lifetime owner. Its Git commands share one cancellation signal, and close is terminal: it cancels commands still running, waits for them and for the object reader to exit, then removes owned state. A failing parallel consumer therefore cannot remove the private objects its siblings are using, and a late read after close fails instead of starting a new reader. The object reader keeps received chunks separate and copies a blob once; concatenating per chunk copied about 8 GiB for one 32 MiB blob. gitBytes settles only after the child exits on every path (exit, abort, deadline, output limit) and kills its process group.

Diffs resolve attributes from the selected head tree only (`--attr-source=<head>`), never the live checkout. Requires Git 2.45.1 or newer: 2.45.0 accepts GIT_NO_LAZY_FETCH but its promisor fetch ignores it (tagged source); on 2.42 a review reproduced a partial clone running its promisor remote's command before isolation. The version check takes the caller's signal and is remembered only once it passes. Concurrent startup commands use settledAll so every one has exited before a failure propagates. gitBytes escalates to SIGKILL two seconds after SIGTERM, kills and waits out the rest of a stopped command's process group when the leader exits (a TERM-resistant descendant with its own stdio does not hold the pipes open), and counts stdout and stderr bytes against one output limit. The batch reader is killed with SIGKILL on close or abort. Conversion detection and path settings read the author's user and system config (AUTHOR_SETTINGS), since those decide what is on disk; snapshot commands themselves never see them.

Measuring this module: compare equal work, and report first-run and warm costs separately. First reads of freshly written files are slow on this Mac, and a warm median hid a deferred fsck. Measure concurrency (eight hash readers beat one; 32 were no faster) and time Git with `GIT_TRACE2_EVENT` before guessing at a bottleneck.
