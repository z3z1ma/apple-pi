Creation ancestry, not the reporting tree, determines temporary ownership. `temporaryCallers` reads durable created/observed caller facts and discarded-identity evidence, with live launch rows as legacy fallback; a missing legacy caller is null, not an inferred manager. The first retained identity fact wins, including null from an earlier disposal; only an unseen ID can use live ownership fallback. A later observed/live caller cannot establish a previous discarded lifetime's provenance. This deliberately leaves indistinguishable old pending cleanup unknown too: absence of a provisional row cannot distinguish old interrupted cleanup from pre-upgrade pre-provisional ID reuse. Known first created/observed callers stay immutable through later disposal. Accounting follows this chain to a lasting person, while lifetime identity also prevents reopening a discarded ID. A transfer can move a temporary person without freeing it from the program; a lasting person moved under it stays lasting and moves to the nearest surviving ancestor on disposal.

Temporary-only tasks can survive the first of several holder disposals but remain financially internal and delete after the last temporary holder disappears. An internal task's discard receipt names a holder in the current disposal, rather than its first historical holder: pending-file checks are scoped to current IDs, so the current launch ownership must survive any failed removal and permit retry.
