External threads deliberately use ordinary `mail` kind and pushed participant rows. Their source id is global per GitHub item or Jira key; the source table owns polling/cursors, not a second subscription list. A first follow, and re-follow after all followers left, starts at the beginning of the command's acceptance second. Existing followers keep their cursor when another person joins; per-recipient mail bodies use each membership's own second-resolution join time, including repository candidates. Full normalized batches stay in shared history.
Why: the operator accepted up to one second of earlier activity instead of silently losing a new event whose provider timestamp rounds down. Exact subsecond ordering is unavailable. Source cursors cannot enforce a later subscriber's start; filtering belongs at outgoing mail construction, while ordinary membership remains its authority. Repository watches discover candidates; they do not subscribe the desk person to each outside item.
Why: thread membership is the existing authority for delivery, inbox and on-call waking. Backfilling old outside discussion on subscription would wake people for unrelated history.

`ExternalCommit` is supplied by the runtime and commits cursor advancement, consumed identities, normalized messages and ordinary mail outbox rows in one transaction before dispatch. Network requests finish before entering it. A poll compares both its captured state and event selection with the current row before committing so a simultaneous re-follow or stop-watch invalidates stale results. Bot-filtered events and quiet CI successes are consumed too; replaying an old success would otherwise erase a newer failure and lose the recovery transition. Check-run failure state is retained across head commits by check name, completion time and id, so a late older success cannot reverse a newer failure. PR commit lists and repository tip comparisons discover intervening commits; pending refs keep unfinished or not-yet-visible check runs observable after the tip moves. Follow seeds the accepted PR head, and polling carries the previous metadata head forward before replacing it; the first poll can follow a force push too. Earlier string-valued CI conclusions are normalized before comparison so their missing watermark fields cannot freeze subsequent state.
Why: deduplication by timestamp alone loses overlapping polls, retries and restarts; advancing a cursor before publication can permanently lose mail. Source APIs expose second-resolution timestamps, so comment queries overlap the previous cursor by a second and identity deduplication removes repeats.

The daemon imports this module directly under Node type stripping; its class fields use erasable TypeScript rather than constructor parameter properties. The focused suite checks native daemon import as well as the Vitest-transformed implementation.
Why: an initial constructor passed TypeScript and in-process tests but blocked every real daemon start with ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX.

Shutdown aborts requests and each awaited continuation checks the abort signal before touching the database. Error events contain fixed operational messages or endpoint paths, not raw authenticated HTTP output or credentials. Jira binds every operation to one credential snapshot, validates it before and after each request and before publication, and rejects reuse of a retained key under another site. Existing membership short-circuits follow only when a matching polling source and pushed delivery already exist. The configured desk must have an open channel and current person, otherwise the fallback receives its batch with a recorded operational warning. Archiving runtime fallback mail leaves it archived; later batches reuse an open successor or create one, instead of failing publication against the closed thread. Outside text is escaped inside a source-evidence boundary before both history and pushed mail.
Why: the runtime closes its only writer connection synchronously on stop, and changing the operator's Atlassian account must not silently turn an old issue subscription into another site's issue.
