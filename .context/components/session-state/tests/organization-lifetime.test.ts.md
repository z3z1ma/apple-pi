These are isolated real-runtime/socket/SQLite tests with real disposable sleep processes and scripted bridges, not paid model or interactive CLI executions. The native SDK case supplies a fixture flag value, then executes the real /incorporate handler with zero provider requests. Loader smoke owns flag/command registration; it does not prove the CLI argument parser or physical window-close path.

Reopen admission waits for the newly observed PID, not merely a sessions row: the row already exists before the replacement hello. The original row-presence barrier falsely read the old pending-close state. Fixture stop is tracked once because Runtime.stop closes its lock and is not idempotent.

The restart case interrupts after the child's permanent marker but before file removal, while its close is deliberately unacknowledged. After restart, no exclusive bridge binding proves that the live writer may be signalled. The test requires blocked cleanup and preserved bytes, explicitly exits its owned stand-in, then requires actual file and row removal. Runtime restart is not permission to kill an unbound writer. A prior timeout expecting automatic signalling was a harness-policy error, not a failed departure guarantee.

An on-call root is included in leaf-first cleanup. Automatic departure notices reach only the operator, so the closing tree cannot awaken itself with cleanup reports. The unassigned backlog assertion preserves the operator's explicit choice; the busy person settles to idle while still holding its assignment before reopen cancellation is tested.
Why: combining busy and assigned state without observing idle/held behavior would let the turn guard mask a broken assignment guard. Stale cleanup is exercised through the socket command and retained file, not a direct guard call. Incorporation replay after a merge must leave the new target unincorporated; event counts alone constrain bookkeeping without establishing that behavior.

The fixture shadows pi on PATH with a failing executable while preserving ordinary process tools. Unexpected wake commands remain observable in the real journal, but cannot launch a paid CLI session.
Why: the on-call close control must be safe when its no-wake assertion fails, not only when production code is correct.
