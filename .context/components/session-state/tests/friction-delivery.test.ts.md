These cases use the actual Runtime, socket commands, journal and transactional mail outbox over a temporary database. The receiving bridge speaks the protocol directly around an owned sleeping process; it is not a model turn, Pi transcript receipt or proof that a manager read or acted on a notice. Fixture SQL writes happen only before startup or between stopped instances.
Why: planner output alone cannot establish durable publication, restart suppression or producer/observer failure isolation. The aborting outbox trigger proves that failed observation publication preserves the already committed dependency and retries without a false raised marker.

Restart uses a new Runtime instance with the same database, preserving durable notification state but discarding the process-local trigger watermark. Resolution and recurrence use public commands, not private helper invocation. A prior applied mail stays applied; the new condition has its own durable outgoing delivery.
