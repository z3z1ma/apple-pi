## file

Code uses local filesystem authority only on explicit renderer requests. Repository discovery reads current/dormant cwd metadata and probes Git roots; it changes no workplace facts. Manual root selection and explicit reference activation are separate entry points; reference decoration is metadata-only. Discovery skips retained cwd values that are missing or no longer repositories, leaving manual paths available rather than making one stale session prevent discovery. Paths must stay within that root after realpath resolution; Git metadata is excluded. The lazy tree does not apply Git ignores and has no result cap. Only existing regular UTF-8 files can be saved; symlink files must be opened through their actual target path.

Reference resolution checks only supplied candidates: no file content, directory enumeration or Git-root discovery. Relative paths require an explicit source cwd and stay inside it; absolute paths and conventional ~/ references work independently of current Code selection. A containing source cwd remains the root, otherwise an absolute reference uses its canonical parent. Root selection compares canonical path ancestors before that fallback: a symlink cwd combined with /var versus /private/var spelling can hide an escaping child symlink from both raw-prefix and canonical-parent comparisons. Invalid or inaccessible candidates stay plain text; an unavailable cwd still permits absolute references. Colon filenames stay literal here; the renderer owns location-suffix alternatives. Contained symlinks return their actual target path. Regular-file metadata does not promise readable UTF-8 or continued existence; the explicit Code read checks those later.

A completed regular-file byte read followed by PDF-signature, NUL or fatal UTF-8 rejection emits a typed non-text failure with its canonical file URL. A valid PDF can contain only ASCII bytes, so successful UTF-8 decoding alone cannot classify a document as editable text. The concrete %PDF- signature addresses that case without extension guessing or a format registry; ordinary text named .pdf remains text. Only the dedicated classification error can add this target; permission, missing-file, containment and other failures cannot acquire it by matching message text. Save remains text-only and emits no external target. URL encoding preserves percent/hash/space/colon filenames for the existing file opener and canonical targets preserve its script/execute reveal guards. The backend still opens no application itself.
Why: the same readFile contract serves explicit activation and passive freshness checks; a content classification alone cannot grant authority to launch another application. Ordinary read failures must remain visible instead of becoming unrelated external-open attempts.

Save is optimistic concurrency, not a cross-process lock: the original byte hash must still match, and path/inode/device/mode/hash are checked again immediately before atomic replacement. There remains a check/rename race against noncooperating editors; this is an accepted limit, not an atomic compare-and-swap guarantee. A unique same-directory temporary file preserves mode, is fsynced, and is removed on refusal. Explicit Save is the only write method. Binary or invalid UTF-8 files are refused without truncation; BOM and line endings remain in the text.

`git()` is the one way this app runs Git, shared with the Git app's backend (backend/git.ts): argument arrays, no pager or fsmonitor, optional locks off, no terminal prompts, `GIT_EDITOR=true`, SSH in batch mode unless GIT_SSH_COMMAND is set, and inherited GIT_* repository overrides cleared. Stdin is always a pipe so callers can pass input; `ok` accepts extra exit codes and `combined` returns stderr with stdout for commands that report progress there.

File discovery is filename/path-only. Inside a Git working tree, ls-files combines tracked and untracked entries with standard ignores; deleted entries, symlinks and non-files are excluded, and results remain relative to the selected directory even inside a repository subdirectory. Plain folders use an explicit directory walk that skips .git and symlink traversal; regular binary files can be listed without reading contents. Only Git's known not-a-repository diagnostic falls back to that walk, with the child locale fixed so other Git failures stay visible.

Worktree discovery: a selected subdirectory resolves to its current worktree top-level, then list --porcelain -z supplies all linked roots. NUL fields and empty-field record boundaries preserve whitespace/newlines in paths and lock/prune reasons. Optional locked/prunable properties are present even when their reason is empty; bare and detached remain separate flags. Missing prunable roots remain metadata rather than being realpathed away. Git top-level output loses exactly its final newline, not meaningful path whitespace. These methods never create, remove, switch or check out a worktree.

Why: agents and the operator share the same files; stale-buffer rejection protects ordinary concurrent edits, but a local hash check cannot lock unrelated writers. Coupled: apps/agent-workplace/src/workspace.ts, apps/agent-workplace/src/electron/main.ts, apps/agent-workplace/src/electron/preload.ts
