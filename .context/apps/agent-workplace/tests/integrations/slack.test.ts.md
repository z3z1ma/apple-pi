## file

The town square and crier use the backend API against a fake Slack Web API. Unread counting stays bounded: history is counted for at most 30 channels, and a read channel is not in the square. Search uses Slack's own highlighted, paged `search.messages` and does not mark anything read. A direct-message hit names the other person. A thread reply's permalink names the thread. The next page returns only the next messages. Excerpts are plain text with matched words marked, cut around the first match of a long message. A channel already in the unread listing takes its last read from `client.counts`; any other channel uses `conversations.info`; a followed thread uses its parent's `last_read`. A non-timestamp is refused and reads nothing. Reopening a channel that was just read shows nothing new. Every call carries the web client's token and the `d` cookie. With only `oldest`, Slack answers from `oldest` forward; otherwise it answers the newest in range.
Why: counting every unread channel's history would make the square depend on an unbounded Slack read.
