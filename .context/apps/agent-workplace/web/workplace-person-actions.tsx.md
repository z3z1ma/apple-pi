Workplace owns one lifecycle provider above retained application views. DM-header/profile menu buttons, sidebar context gestures and actual Org people cards request its shared context menu; opening a menu is metadata-only. Organization-name work/Rename and ordinary profile/drag/read actions stay separate. Former, missing, operator and temporary identities have no lifecycle actions. Let go is available for current lasting people regardless of role title or independent status; the operator's runtime request owns report, assignment, delegation and cleanup safeguards, plus a handoff when requested. Snapshot changes never replace an in-flight operation or its original names/results.
Why: a role title describes a person's role, not their eligibility for departure. Using it as a UI gate hid independent/unroled people and duplicated a policy that the operator's runtime request must enforce.

Call-in derives only the selected person and absent ancestors to the recorded head, walking through awake managers and excluding reports. Missing, former, temporary, incomplete or cyclic chains block the preview. Extra absent people require named confirmation; a singleton launches once from the explicit menu choice. Expected IDs and operation UUID stay unchanged across retries; the backend validates consent and reconciles command IDs before continuing. Closing and making another explicit choice creates a new operation. This is dialog-local state, not a persisted plan or global cascade policy.

Send home and Let go affect only the selected identity. Preserve World's existing decision: idle Send home starts immediately from the menu with confirmed:false, pinned to false even if a newer snapshot becomes busy before the effect. Busy/awaiting-input selections require a warning and explicit Send home click. An automatic idle attempt that returns confirm:true stays in the same dialog and requires that later explicit click; snapshot changes alone never auto-confirm. A synchronous request lock prevents duplicate submits and pending cancellation. Retirement requires a trimmed reason and explicit permanent acknowledgment. Its separate handoff choice defaults on and stays disabled with the other fields during pending or uncertain requests; accepted/delivered receipts remain unconfirmed completion. Transport failures for these non-idempotent APIs disable blind retry, unlike call-in's same-ID reconciliation. Membership and session status remain snapshot-owned; no optimistic removal or rollback belongs here.

Sending home the head of an unincorporated organization dissolves it, so the runtime refuses such a close unless the request carries `dissolve: true` (`{ok:false, dissolve:true}`). The dialog then replaces its reversible-sleep promise with the consequence and offers two explicit choices: Incorporate and send home (incorporateOrganization, then the ordinary close) or Send home and dissolve, enabled only after "Permanently let this organization go" is ticked. Even the automatic idle attempt therefore never dissolves anything (operator, 2026-11-06). Once incorporation succeeds the dialog leaves that choice state at once, and the following close's refusals go through the same transition as an ordinary Send home, so a busy refusal still makes the next Send home click confirm interruption. The embedded World has no dialog of its own: its End session hands a dissolve refusal to this provider through `window.parent.agentWorkplaceSendHome`, which opens the dialog directly in the choice state. Standalone World (no host) keeps showing the refusal as a notice.
Why: a second copy of the choice in World would drift; review review-6dff9d59 found World's End session was a dead end and that the incorporate branch dropped busy refusals.

Why: the shared menu retains callbacks across snapshot updates, so selection rechecks the current identity instead of using the menu's captured eligibility. Once an operation opens, its consent and outcomes stay fixed; recomputing them could silently approve additional launches or erase partial results. The automatic idle request stays explicitly unconfirmed because a newer busy snapshot is evidence of work, not operator consent to interrupt it.

The native dialog captures Escape before underlying profile listeners, remains mounted above hidden views, and restores only its still-connected original trigger. It retains refused/partial/uncertain outcomes after the selected profile disappears. Ignoring page/component disposal is not cancellation of an issued backend action.
