Mount one retained component inside Code's center editor pane. App-tab, repository and panel-visibility changes retain each terminal and its output. The selected repository seeds only a new session; existing root props are immutable and the returned canonical cwd labels that session's seed directory. Full renderer navigation/reload is a different lifetime: main closes old terminals after navigation commits, and the shell's one beforeunload guard warns while this component reports starting/running sessions. Exit tabs do not count as live.

Mounting an empty panel performs no terminal API call or subscription. An operator-created child subscribes before create and supplies its own identity, because initial output may arrive before the invocation reply. Matching data establishes a live connection before Ghostty processes that output, so cursor/device queries can send their reply while create is still pending. After an exit event, later data may still render but never re-enables input. Cleanup removes subscriptions/observers and disposes the Ghostty terminal; explicit close is idempotent across the button and child teardown. Uncertain IPC errors retain a live count until an exit or explicit close establishes the result.

Ghostty0.4.0's public Ghostty.load(explicitAssetUrl) and Terminal({ghostty}) avoid init's default data-URI loader. The local WASM is emitted by Vite via the package's exported asset, and only wasm-unsafe-eval is added to the existing script CSP. The shared compiled engine outlives individual terminal instances; each instance owns its buffer, listeners and renderer.

The terminal uses one constructor-only high-contrast dark palette in both app appearances, with the host viewport using the same background; surrounding controls follow the application theme.
Why: the pinned package lacks a supported faithful live default-color update. The options.theme setter warns that post-open changes are unsupported, renderer.setTheme leaves stored core cell colors unchanged, and OSC4/10/11/12 color setters lack their required WASM allocator. Constructor-only styling preserves shell/output state without unsupported mutation or a second output history. Test interior blank terminal cells, not only the unoccupied canvas fringe: the latter previously changed color while actual cells remained white on a dark pane. Cover initial creation in both appearances and retention when the application theme changes.

Output has no host clipboard bridge or link-opening callback. Electron denies new windows, so terminal output cannot launch a browser by emitting an escape sequence. User selection/copy remains distinct from OSC52-driven clipboard authority. Real native IPC, terminal application behavior and process hangup require the isolated Electron checks; browser fixtures prove only renderer behavior.
