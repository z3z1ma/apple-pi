## file

Workplace owns one lifecycle provider above retained application views. DM/profile ellipsis buttons and actual Org people cards request its shared context menu; opening a menu is metadata-only. Organization-name work/Rename and ordinary profile/drag/read actions stay separate. Former, missing, operator and temporary identities have no lifecycle actions. Let go is available for current lasting people regardless of role title or independent status; the operator's runtime request owns report, assignment, delegation and handoff safeguards. An unroled person is not an ineligible identity. Snapshot changes never replace an in-flight operation or its original names/results.

Call-in derives only the selected person and absent ancestors to the recorded head, walking through awake managers and excluding reports. Missing, former, temporary, incomplete or cyclic chains block the preview. Extra absent people require named confirmation; a singleton launches once from the explicit menu choice. Expected IDs and operation UUID stay unchanged across retries; the backend validates consent and reconciles command IDs before continuing. Closing and making another explicit choice creates a new operation. This is dialog-local state, not a persisted plan or global cascade policy.

Send home and Let go affect only the selected identity. Preserve World's existing decision: idle Send home starts immediately from the menu with confirmed:false, pinned to false even if a newer snapshot becomes busy before the effect. Busy/awaiting-input selections require a warning and explicit Send home click. An automatic idle attempt that returns confirm:true stays in the same dialog and requires that later explicit click; snapshot changes alone never auto-confirm. A synchronous request lock prevents duplicate submits and pending cancellation. Retirement requires a trimmed reason and explicit permanent acknowledgment; accepted/delivered receipts remain unconfirmed completion. Transport failures for these non-idempotent APIs disable blind retry, unlike call-in's same-ID reconciliation. Membership and session status remain snapshot-owned; no optimistic removal or rollback belongs here.

Why: the shared menu retains callbacks across snapshot updates, so selection rechecks the current identity instead of using the menu's captured eligibility. Once an operation opens, its consent and outcomes stay fixed; recomputing them could silently approve additional launches or erase partial results. The automatic idle request stays explicitly unconfirmed because a newer busy snapshot is evidence of work, not operator consent to interrupt it.

The native dialog captures Escape before underlying profile listeners, remains mounted above hidden views, and restores only its still-connected original trigger. It retains refused/partial/uncertain outcomes after the selected profile disappears. Ignoring page/component disposal is not cancellation of an issued backend action.
