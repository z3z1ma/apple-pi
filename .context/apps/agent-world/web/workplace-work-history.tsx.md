## symbol:WorkHistory

The team filter uses the task's recorded headquarters exactly, not today's reporting ancestry. A people filter selects actual assignment participants across organizations and labels the original anchor. Finishing an assignment is displayed separately from a task's done status; it is not proof that the whole task completed. Missing history in an older snapshot is distinguished from an empty known history. The inline summary stays compact. Organization cards/selected headings use the render callback to compose their native name trigger and this summary; the callback receives the real open action, not a hidden button or a second modal state. These callers omit a separate history button. Profiles with recorded tasks use a native, descriptive View all button in the Work header, rather than a second action below the preview. It focuses itself before opening so dialog dismissal returns to that precise control without closing the profile. Either entry opens the same viewport-bounded native modal with independently scrolling task navigation and detail, retaining every record without a result cap. Names also open empty/unavailable histories; the modal preserves that distinction instead of presenting unavailable metadata as a known zero.

Task bodies mount only after an explicit Read task click. Reading registered task content is observation, not reading a thread/transcript; no seen or participation operation belongs here. Markdown keeps the existing escaped renderer and external-link bridge. Within Workplace, recorded task.project supplies the local-file cwd, and both body references and the displayed bundle/task.md path use the stat-only resolver. Explicit file activation closes this modal before navigating to retained Code and focusing its editor; other drafts stay retained. It adds no implicit task-body read or conversation acknowledgment. Opening the modal is metadata-only; selecting a task mounts its body reader. Closing the modal unmounts the body reader and ignores its pending results; it does not cancel an already issued backend read. It keeps an underlying profile open and restores the precise name or View all trigger.
Why: moving a person must not rewrite which team did historical work, and merely browsing organizational metadata must not acknowledge conversations or fetch every task body. The task API has no abort argument; ignoring late results protects the closed view without claiming the backend stopped reading. WorkDialog captures document.activeElement when it mounts, so each entry must focus its actual trigger before requesting open; otherwise closing can return focus to an older profile control instead.
