## file

File-reference navigation supplies an immutable fileRequest with backend-validated root/path and optional positive line/column. Code selects that root before using the existing guarded openFile path, retains all other buffers/models, and reveals/focuses the clamped position once the target model exists and Code is visible. Each request is consumed once; later repository changes must not reopen it. The same literal file without a location opens at the start. Missing/deleted files show the existing Code read error rather than an external-open fallback. Decoration itself never reads file contents.
Why: a first-visit file activation can arrive before repository selection, Monaco loading and model creation complete. Applying focus or caret position earlier loses that navigation; replaying it on later root changes overrides the user's next action.

The shell keeps Code mounted after its first visit and passes visibility through `active`. Its dirty callback covers retained buffers in every repository, not only the selected file. The shell owns renderer unload prevention through that aggregate dirty callback; native confirmation belongs to Electron's `will-prevent-unload` handler. Both layers follow that single confirmation path.
Why: unmounting on application navigation discards unsaved drafts and worker/model ownership. Reporting only the selected file as dirty lets World navigation lose drafts from a different repository. A separate renderer confirmation would duplicate the native leave decision.

Keep each workspace root in the Monaco model URI namespace, including for overlapping directory roots. A clean buffer can adopt a reread disk version automatically; a dirty buffer advances its save base only after a successful save or an explicit resolution against the observed external version. A disk read started against an older base must not replace the result of a completed save.
Why: `/repo` plus `sub/file.ts` and `/repo/sub` plus `file.ts` are separate retained drafts of the same physical file. A shared Monaco URI makes model creation fail; merging those drafts implicitly would lose user edits. Base hashes describe disk versions, not draft text, and the backend's optimistic conflict checks remain the write authority.

Explicit tab closure is the exception to buffer retention: close only current-repository targets, confirm the entire dirty/conflicted set before removing any buffer, detach an active model before disposal, and dispose listeners/models only for removed buffers. Cancel preserves every target and performs no save. Closing is blocked during an in-flight save; pending disk reads must ignore a buffer removed or replaced in the map. Resolve menu close targets, tab order and current selection at action time: the shared menu retains callbacks while an outstanding file read can add/select another buffer. Restore focus to the surviving tab or Files pane only while Code is visible.
Why: closing is a local draft/resource decision, not a filesystem write. A delayed read must not touch a disposed model, and bulk closure must not partially discard work before the operator can cancel.

Quick Open mounts only for an explicit search action in active Code; the picker fetches filenames and delegates a selected result to the existing guarded openFile. Existing open-buffer disk checks remain a separate content-read path. Worktree metadata uses the canonical Git top-level only for discovery/display: it must not replace the selected directory's file-list root. Choosing a linked worktree selects a directory and retains visited roots/drafts; it never checks out a branch. Optional locked/prunable flags use property presence, including empty reasons, and bare/prunable entries remain labeled disabled metadata.
Why: a manually selected repository subdirectory has a different relative-path basis, and read-only discovery is not Git mutation or permission to open every listed path.

One retained WorkplaceTerminal occupies the bottom of the center editor pane, leaving Files/Git at full height. Code forwards its live-session count separately from dirty buffers to the shell's existing leave guard; root/app-tab changes retain the component and its sessions. Terminal creation, PTY cleanup and committed-navigation lifetime belong to the terminal component/main process, not Code's file models or a second unload handler.
Why: a running shell can need leave protection even when every file is clean. Cancelling a navigation must preserve that shell; disposing it during the unload attempt would defeat the operator's Stay choice.

Git diff preview belongs to the center pane and is read-only. Hiding the editor for a preview keeps its Monaco host, models and drafts mounted; Close diff restores the selected file, file selection exits preview, and repository changes clear only preview selection. Pass a stable onDiff callback to GitPane so ordinary editor redraws do not trigger another patch read.
Why: a diff request is not a file edit, and moving the preview out of the narrow Git status sidebar must not replace a model or lose its unsaved text.

Keep my draft explicitly adopts the observed external text/hash as the save base while preserving the editor text. It clears the conflict without issuing a write; only a later Save can replace that reviewed version, and the backend must still reject a newer disk hash. The adjacent consequence text is part of this decision, while the existing discard action replaces the draft with disk content.
Why: conflict recovery must preserve operator work without silently treating stale draft text as newer disk state or bypassing the write guard.

Normalize CSS shorthand hex values before passing appearance tokens to Monaco themes. `getComputedStyle` preserves custom-property values such as `#fff` rather than expanding them.
Why: Monaco rejects that shorthand with `Illegal value for token color: #fff`, which removes the editor during initialization despite passing static checks. The actual editor-load fixture exercises this boundary.
