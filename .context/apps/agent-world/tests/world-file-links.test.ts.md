## file

This suite loads built Workplace, the shared safe transcript renderer and real Monaco. The preload API is an in-memory fixture: resolvePaths returns only a finite list of known targets, while readFile records content reads separately. It does not reimplement candidate parsing, filesystem stat, confinement or symlink handling. Those are backend tests' responsibility. A cross-project absolute target resolves to its containing directory, not an invented Git root; a relative task reference uses task.project, not the bundle directory. Unknown mail authors provide no guessed cwd.

Metadata profile/history opening must leave transcript reads, task-body reads and file-content reads untouched. Only selecting a task fetches its body. File decoration may resolve metadata but must not read contents. Once Code is activated it intentionally rereads its current buffer on activation and window focus. After activation, compare exact unique root/path targets rather than demanding one read per click; preserve strict zero-content-read assertions before activation. Returning to another repository exposes retained tabs, which the operator selects explicitly to recover that draft. The generated link's public accessible name is Open file: followed by its displayed text. Duplicate literal references remain separate links without nested anchors, escaped HTML remains text and external web links keep their explicit opener. One real spaced filename is activated from Markdown inline code and quoted plain Mail; quotes and backticks remain visible in plain Mail, while inline code keeps its normal Markdown wrapper. This checks whole-candidate recognition without inventing shell parsing or joining arbitrary words. The fixture blocks and records remote requests rather than permitting the safety probes to contact the network.

Position proof uses keyboard activation followed by typing into the real editor: inserting at line 3, column 5 must produce 0123HERE456789. Direct Monaco objects or production test hooks would bypass focus, lazy Code loading and selection timing. A literal colon filename separately verifies that an actual exact filename wins over location suffix interpretation. The task case activates the displayed task-document path as well as a body reference, requires the native history dialog to close, and retains a dirty file while another opens. Deleted-after-decoration targets use the normal Code read error without saving or discarding the existing draft.

Explicit non-text activation uses the existing openFile fixture route and creates no editor tab; missing/default-handler failures remain visible. The non-text case first keeps a dirty text model and changes its disk read to typed non-text: activation/focus freshness must show an error without an OS request, and reopening that retained buffer preserves the draft. Only explicit new non-text activation may call the system handler. Permission failures never fall back. The fixture proves renderer intent, while backend tests prove actual content classification/containment and opener guards.

Run only against the integration owner's named frozen build, one worker, in the shared Chrome sequence. AGENT_WORLD_SHOTS saves light/dark/focus and mail/task evidence. This fixture proves renderer requests and visible behavior, not real filesystem resolution, native IPC or persistent writes. The typed terminal fixture has an empty resolvePaths response solely to satisfy the extended WorkspaceApi; its terminal behavior is unchanged.
