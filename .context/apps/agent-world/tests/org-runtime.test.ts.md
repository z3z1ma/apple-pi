The test uses the real Commands socket, isolated runtime, database and World reader. Only the launched Pi executable is replaced: it reads its assigned goal, sends hello, records incoming bridge commands and acknowledges them without running a model. Headless child processes inherit the isolated agent directory and fake PATH; runtime shutdown owns their cleanup. No tmux server or live workplace is contacted.

The report (the head's direct teammate) exits before sending its bridge hello while a marker file exists. Its real start already persisted goal work and queued assignment mail, whose command ID is nested under the preparation ID. Retry must identify only start commands, preserve that person's identity and existing goal, and launch after its manager connects. Choosing to begin with ready teammates establishes the single head kickoff before the marker is removed. Its body carries the goal first and a roster containing only the ready head; the complete body must arrive only at the head. The late report then produces one channel readiness delivery to the head, not to the report. Assertions use the public Org progress, World task board, actual process launches, received bridge messages and retained thread history, rather than freezing preparation-command payloads, kickoff command IDs or the exact number of failed launch attempts. The launch checks require one head, a retried report with its original goal on every attempt, and a ready manager before each launch.
The operator joins as a pull participant: channel updates wait to be read instead of being pushed as mail. Check the operator's unchanged channel cursor immediately after this join, before its readiness post. An author's own post advances its cursor through that message; that is not an automatic channel read caused by joining.
