# Experiment cycle

Learn something that changes a decision. Read and follow the [shared process conventions](../handbook-writing/references/processes.md).

A `research-lead` owns a multi-person inquiry; a bounded experiment can stay with its problem owner. Include the relevant investigator, an authorized builder/operator and independent evidence challenge. `principal-ux-researcher` designs user-behavior questions; `scientific-skeptic` challenges inference.

1. **Define the discriminating result.** State the decision, competing explanations, prediction, control, observation and how each possible result changes the choice. Agree the target, permitted effects and stopping conditions before running it.
2. **Build the cheapest valid test.** Reuse [research](../research/SKILL.md), [prototype](../prototype/SKILL.md) or an existing test seam as appropriate. Verify that the observation can distinguish the claims. When implementations can be ranked by a meaningful command, use the existing `search_branches` capability rather than invent another optimizer.
3. **Run and challenge.** Preserve the setup and results, including failures and confounds. Have the challenger test what else could explain the observation. Change the test transparently if it cannot answer the question; a redesigned test is a new comparison.
4. **Decide from the evidence.** The authorized owner continues, changes direction, stops or names the remaining uncertainty and next inquiry. Report the experiment's limits and restore its temporary effects.

Done is a reproducible observation and its decision consequence. A synthetic case, role-play or before/after result proves only what its design supports; it is not evidence of real user behavior or general causal benefit by itself.
