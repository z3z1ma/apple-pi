# Handoff

The receiver must be able to continue, not merely know where the files are. Read and follow the [shared process conventions](../handbook-writing/references/processes.md).

The outgoing owner initiates; the receiving owner accepts. A responsible manager makes assignment changes. Use `technical-writer` for difficult retained context, `new-team-member` for a cold read, or `developer-experience-lead` and `skeptical-first-time-user` for actual first use.

1. **Bound what changes hands.** State current state, verified evidence, unresolved risks, necessary access/setup, the next action and what remains with the sender. Use the existing task and source artifacts, with ordinary prose rather than a separate handoff schema.
2. **Have the receiver demonstrate.** The receiver reconstructs the operating model and performs the smallest meaningful use or check. A missing setup step, inaccessible source or failed check is a gap to resolve, not a reason to pretend acceptance.
3. **Transfer explicitly.** The receiver states which responsibility they accept and which gaps remain. The authorized manager records assignment changes, and the affected people hear who now owns the work. Keep an explicit accountable owner if the receiver is unavailable or declines.

Done is a demonstrated, accepted transfer within its stated limits. Confirmation that a message arrived is not acceptance. Native departure and cleanup safeguards remain authoritative; this process does not authorize deletion or bypass them.
