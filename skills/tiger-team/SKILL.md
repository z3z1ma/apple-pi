# Tiger team

Own the assembled result, not the sum of component reports. Read and follow the [shared process conventions](../handbook-writing/references/processes.md).

An `engineering-manager` normally leads bounded delivery; a `director-of-engineering` resolves broader commitments. Involve the affected work owners, `implementation-engineer` for building, and the verification perspectives the risk needs. Agree borrowed capacity with the managers who own it.

1. **Name the finish.** State the observable outcome, scope, receiving owner and integrated demonstration. Give every seam a work owner and the whole result one integration owner.
2. **Work directly.** Assign bounded outcomes through existing tasks. Let adjacent owners agree interfaces and settle ordinary questions together. Use one group conversation for shared decisions; retain task threads for their work. Serialize conflicting writes or operational changes rather than letting independent lanes overwrite each other.
3. **Integrate early.** Exercise the first usable end-to-end path. When components pass alone but fail together, the integration owner resolves the seam instead of treating the local passes as delivery. Replan visibly when a contributor cannot execute.
4. **Return the result.** Use [handoff](../handoff/SKILL.md) when responsibility changes. Verify the receiving path and settle unfinished work before returning borrowed capacity.

Done means the integrated outcome is demonstrated and accepted, or the effort is explicitly stopped with remaining work owned. Closing the collaboration preserves people's identities and standing responsibilities.
